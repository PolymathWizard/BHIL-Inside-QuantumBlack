# Chart families

Pick the chart from the question. The corpus uses a small stable of
families, each mapped to a question class.

## The working set

| Family | Use when |
| --- | --- |
| Stacked survey bars | The argument depends on composition across the same categories |
| Ranked bars | The order is itself the finding |
| Cohort comparison bars | The gap between segments matters |
| Maturity ladder | The story is movement toward scale |
| Waterfall or value bridge | Value is created or eroded across steps |
| Mekko or market map | Both category size and internal composition matter |
| Bubble or scatter | Position and size carry separate dimensions |
| Heatmap or value pool | The pattern across many cells matters more than one exact number |
| Scorecard or dashboard | Key metrics need quick reference at consistent density |

## Build rules observed

* Use stacked bars when composition is part of the argument; use simple
  bars when only rank matters.
* Bars compare the same categories in the same order across paired charts
  so the eye can diff them.
* Direct percentages cut dependence on a separate legend.
* Source and rounding notes stay below the evidence.

## The question to ask

Does the reader need composition, rank, change over time, or a threshold?
Answer that first and the chart family selects itself. Reversing the
order, picking a chart because it looks sophisticated, is the most common
way otherwise-good teams break the exhibit grammar.

## What the corpus avoids

Pie charts for anything argumentative, dual axes that invite misreading,
3D effects, and gradient decoration. Absence of these is part of the
fingerprint. Tier: CORROBORATED across the T1 and T6 corpus.
