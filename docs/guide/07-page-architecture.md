# Page architecture

The page reads in a fixed order even when the topic changes. Hierarchy is
the delivery mechanism for the answer-first rule.

## The wireframe

From top to bottom, a typical page runs:

1. **Practice or topic kicker.** Small caps, quiet, orients the reader.
2. **A conclusion written as a headline.** The answer, not the topic.
3. **One sentence of framing.** Adds scope without delaying the point.
4. **Key takeaways box.** Three to five bullets that restate findings,
   not process.
5. **Exhibit block.** Numbered, with a title that states the result in
   chart-specific form.
6. **Source line.** Dataset, sample, dates, notes.

## Hierarchy rules

* Headline carries the answer.
* The deck adds scope, not a second thesis.
* Takeaways compress the page into decisions.
* Exhibit title states the result in chart-specific form.
* Source and method are quiet, consistent, and easy to find.

## The visual reading order

Headline, then takeaway, then evidence, then implication, then source.
Design every page so a reader moving in that order never has to backtrack.

## Typography register

Serif display for headlines, a clean sans for body and labels, a mono
face for kickers and source lines. The mix is conventional; the
discipline is in never letting decorative type interrupt the reading
order. Recorded as observation only; your artifacts use your own faces.

## The test

Hand the page to someone for fifteen seconds, then take it away. If they
can state the finding, the architecture works. If they can only state the
topic, the headline is a label wearing a headline's clothes.
