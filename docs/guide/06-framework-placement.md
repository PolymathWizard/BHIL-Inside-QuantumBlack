# Framework placement

Diagnostic constructs tend to appear early. Prescriptive constructs tend
to arrive later. The placement of models mirrors the order of the
executive argument.

![Framework placement map](../assets/framework-placement.svg)

## Reading the move

1. **Open with diagnosis.** Constructs like the paradox statement, the
   two-axis arena model, and trend scoring appear early to size the issue
   and create tension.
2. **Build the case.** Early constructs translate data into a clear frame
   so the opportunity is visible before any named model arrives.
3. **Turn to prescription.** Capability concepts, agent architectures, and
   factory or tooling systems appear later to move from insight to action.
4. **Close with implementation.** Roadmaps and high-performer cohorts
   arrive last, anchoring the plan and signaling how to win.

## The typical flow

Diagnose, then compare, then frame, then prescribe. Four moves, in that
order, across report after report.

## Why placement matters more than the framework itself

A prescriptive model introduced before the evidence reads as a sales
pitch. The same model introduced after an exhibit cascade reads as the
natural name for what the reader has already seen. Placement converts a
framework from decoration into conclusion.

## Using this as a designer

When laying out a report, position construct pages against this map. If a
named model lands in the first third of the document, check whether it is
doing diagnostic work; if it is prescribing, move it. The construct
inventory with observed positions lives in `data/constructs.csv`. Tier:
CORROBORATED for the placement tendency; individual construct rows carry
their own artifact citations.
